## 项目经历（STAR 写法，可整段放进简历）

**项目：AI Incident Copilot——面向工程师的 AI 故障诊断平台（个人项目，2026）**

- **完整闭环**：独立设计与实现「日志接入 → 自动事故识别与去重 → 规则引擎 + Agent 调查取证 → Runbook/历史案例检索（RAG）→ 结构化诊断（根因假设/影响范围/排查建议）→ 人工反馈 → 离线评测」全链路，FastAPI + SQLite 单机可跑，带实时 Dashboard。
- **诊断可信度工程**：每条结论强制引用带编号的证据（证据日志 [E#]/调查笔记 [N#]/手册 [R#]/相似事故 [S#]）；引用护栏自动拦截模型编造——伪引用自动标注降级并把所在假设的置信度封顶 0.35；材料全空时模型如实"弃答"而不是编答案；全链路 Trace 实录实际执行过程与降级原因。
- **RAG 检索优化**：修复手册类型误标（关键词计分制）、查询改写与多查询融合全配置消融实验；27 例故障集 Runbook Top-1 从 55.56% 提升到 88.89%，Recall 77.16%→84.57%，P@3 74.07%。
- **评测体系搭建**：LLM-as-Judge 开卷评测（发现并修复"裁判看不到检索资料、把合法引用误判为幻觉"的测量缺陷）；4 种检索后端消融对比基准；评测报告自带数据集/语料指纹与模型配置自证，防止旧成绩冒充新评测。
- **工程质量**：235 项自动化测试全绿并持续反向验证；诊断结果事务原子性、后台任务幂等与断电恢复、跨时区日志统一 UTC 时间账本、旧库自动迁移与外键完整性体检；可选 API 钥匙门锁 + 请求大小/写入频率限流，凭据零泄漏。

## 面试可能被追问（如实回答参考）

1. **"幻觉率 0% 怎么做到的？"** → 不是数学意义的零：是裁判在 27 例样本内未检出。靠三层约束：① 每条结论必须引用本次真实提供的证据编号；② 无证据时模型直接弃答；③ 裁判与诊断同源材料（开卷评测），编造才判为幻觉。局限性（小样本、裁判与诊断同模型的自评偏置）也写进了报告。
2. **"数据是真实的吗？"** → 27 例模拟故障集（含对抗性案例），标签经人工核对；真实生产数据尚未接入，报告如实标注。
3. **"哪部分是你自己写的？"** → 按你的实际参与情况回答（建议：架构设计与需求定义主导，编码过程使用 Claude Code AI 辅助，但每个修复都经过测试验证与数据裁决——这个说法与项目记录一致）。
