## 待修改：仍归入 R05 / F12

### P1：标准评测命令在打印结果时异常退出

位置：`eval/run_eval.py:727` 的 `main()`，特别是第 778 行。

新增 `provider_distribution` 是字典，控制台打印仍对除耗时和失败数以外的指标使用 `:.2%`。因此运行标准评测入口时，评测与报告生成后会遇到：

```text
TypeError: unsupported format string passed to dict.__format__
```

新增 token、弃答和引用降级计数也被错误打印为百分比。报告已写入不代表入口成功退出，自动化脚本会把这次运行判为失败。

复现方法：先真实执行 27 案例的 `run_eval`，把报告输出到隔离审计路径；随后仅替换 `main()` 内的 `run_eval` 返回该真实报告，设置默认命令行参数并运行未经修改的打印逻辑，稳定得到上述异常。这样避免覆盖仓库标准报告。

建议：命令行和 Markdown 报告共用明确的指标类型格式化规则。验收必须运行完整 CLI，确认退出码为 0、字典正常展示、整数计数不带百分号；不要只测 `write_report()`。

### P2：自定义数据集的报告指纹指向了默认文件

位置：`eval/run_eval.py:88`、`:158`、`:228`。

`run_eval(cases_path=...)` 支持替换数据集，但 `_evaluation_environment()` 固定读取 `DEFAULT_CASES_PATH`，报告名称也固定写 `eval_cases.json`。这会让另一份测试集被错误标记成默认集。

独立复现：临时创建仅含一个案例、且修改案例 ID 的 JSON 文件，实际执行评测。结果：

```text
total_cases: 1
actual_hash:   16387aa8187ee2e8
reported_hash: 4706b5ee514c39f4
default_hash:  4706b5ee514c39f4
```

建议：将实际 `cases_path` 传入环境记录，报告同时记录实际文件名和内容指纹。验收用两份不同数据集分别运行，检查报告指纹与各自文件一致。

### 指标解释边界

`total_tokens` 目前仅收集最终诊断 trace 中可解析的 usage，未覆盖所有 Agent 决策、改写或裁判调用；缺少 usage 时聚合为 0。因此不能将它称为完整调用成本。后续应区分未知、部分统计和确实为零，并明确统计范围；若目标是全流程成本，再汇总所有调用。当前 Mock 的 0 token 不能作为真实模型成本证据。
